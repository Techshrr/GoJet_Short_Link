# API 与自动化

其他应用需要在不操作浏览器界面的情况下创建、读取或管理工作区内容时使用 GoJet API；其他系统需要自动接收 GoJet 中发生的事件时使用 Webhook 通知。

## API 请求鉴权

在工作区中创建只包含集成所需权限的 API 密钥，并通过 HTTPS 请求的 `Authorization: Bearer <API_KEY>` 请求头发送。不要把 API 密钥放入 URL、前端打包文件、统计字段、日志或源码仓库。如果怀疑密钥已经暴露，应立即撤销并创建新密钥。

## 让重试不会造成重复操作

接口要求 JSON 时使用 JSON 请求体，保存 GoJet 返回的资源编号，并在列表存在多页时按照接口返回的分页信息继续读取。对于明确支持幂等写入的接口，重试同一个业务请求时复用相同幂等标识，避免因为网络重试重复创建内容。

## 明确处理错误状态

`401` 表示没有有效鉴权信息；`403` 表示已经鉴权但当前密钥没有执行此操作的权限。文档明确说明的场景中，`409` 表示当前状态存在冲突，例如公开短路径已经被占用；`422` 表示提交数据没有通过验证或策略检查；`429` 表示当前请求频率过高，应按照接口返回的限流信息降低请求速度并稍后重试。

## 验证 Webhook 通知

处理 Webhook 内容之前先验证 GoJet 签名。使用投递编号保证重复投递不会造成重复业务处理，为失败投递保留足够的排查信息，并在接收系统已经可靠保存或排队事件后再返回成功。不能为了让联调暂时通过而关闭签名校验。

## 保持网页操作与 API 操作一致

API 写入使用与网页操作相同的工作区权限和已保存资源状态。跳转、内容可用状态、账号限额和安全判断由处理请求的服务决定，因此集成必须根据返回结果确认操作状态，不能仅根据本地请求发送成功就假定服务端已经完成修改。

具体接口示例请继续查看 **API 参考**。
