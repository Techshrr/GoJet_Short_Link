# Security

## Account security
Use strong passwords, email verification, session controls, MFA where enabled, and least-privilege OAuth/workspace permissions.

## Platform security
Authorization, CSRF, secret handling, rate limits, and high-risk governance are server-enforced. The UI does not become a security boundary by hiding a control.

## Destination risk
Risk decisions use provider/evidence pipelines on the server. Customer views expose actionable status without leaking internal provider evidence that would weaken detection.

## File scanning
Uploaded file availability follows scanning state. ClamAV integration and worker results are treated as server truth.

## Abuse and audit
Abuse reports, security events, and audit records form an operational trail. Administrative state changes that require a reason must record it.

## Responsible disclosure
Use the deployment's published security contact. Do not send secrets, credentials, or unnecessary personal data in an initial report.
