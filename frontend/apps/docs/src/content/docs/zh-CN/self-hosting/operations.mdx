# 维护、备份与回滚

首页可以正常打开并不能证明 GoJet 所有服务都正常。升级前后应分别检查关键服务，并把恢复所需资料保存到被保护服务器之外的位置。

## 检查服务状态

分别确认短链接跳转服务、平台 API、后台 Worker、邮件 Worker、文件扫描 Worker、数据库、Redis 和当前存储服务。随后完成一组小型端到端检查：登录账号、进入工作区、创建或打开一条短链接、使用管理员账号进入后台，并确认当前启用的邮件或文件流程。每一个失败项都应单独记录，不能用写死的全绿状态代替真实检查结果。

## 备份持久化数据

备份 MySQL，以及所有包含用户上传文件或其他必要资产的持久化存储位置。加密密钥和环境配置应单独保护，避免获取某一份备份的人同时得到使用所有敏感数据所需的全部密钥。定期执行恢复测试；生成了备份文件并不等于这份备份一定可以恢复。

## 安全升级

先阅读版本说明和数据库迁移要求。创建并验证备份，根据版本说明停止或排空需要暂停的任务，只执行一次数据库迁移，部署新二进制文件和已构建前端资源，重启所需服务，然后依次检查短链接跳转、账号登录、工作区页面、管理员登录、支付回调、文件扫描和邮件。

## 部署前确定回滚方案

回滚同时涉及应用文件和数据库兼容性。如果某个版本包含无法安全反向执行的迁移，应使用文档规定的向前修复或备份恢复方式，不能简单把旧二进制文件覆盖到已经升级的数据库结构上。在新版本通过要求的检查之前保留上一份可部署安装包。
